<!-- sdlc:auto:start overview -->
This is 'attendence tracker', an attendance management system generated by the Quorq AI SDLC platform. It is a two-application repository: a Vite + React 19 single-page frontend containing all approved, reviewed screens (currently running on seeded sample data, not wired to a real API), and a FastAPI 0.115 backend scaffold that currently exposes only a health check, since no backend architecture had been approved when it was generated. The backend uses SQLAlchemy over a local SQLite database by default (switchable via DATABASE_URL), and docker-compose provides Postgres and Redis services for the eventual approved architecture.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js (for the frontend, Vite 6 / React 19 toolchain)
- Python 3.12
- pip
- Docker and Docker Compose (optional, for running Postgres/Redis via docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Backend: cd backend && pip install -r requirements.txt
3. Backend: uvicorn app.main:app --reload (creates ./app.db SQLite file on first run; no setup needed)
4. Frontend: cd frontend && npm install
5. Frontend: npm run dev
6. Optional: from the repo root, docker compose up to start Postgres (port 5432) and Redis (port 6379) for architecture components beyond the current stub backend
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one FastAPI router per architecture component that owns endpoints (backend/app/routers/)
- Generated backend routes are stubs returning a typed StubResponse until implemented
- SQLAlchemy models inherit from the shared Base in app/database.py; main.py imports app.models before calling Base.metadata.create_all so tables register
- Database defaults to local SQLite (sqlite:///./app.db); override via the DATABASE_URL env var to point at Postgres/MySQL without code changes
- CORS allowed origins are configured via the ALLOWED_ORIGINS env var (comma-separated), falling back to localhost Vite dev origins
- Frontend screens live under src/screens/ (per README) and currently render seeded sample data rather than calling the backend
- Frontend API access is centralized in src/lib/api.ts (apiFetch), using VITE_API_BASE_URL and VITE_API_SECRET_KEY env vars with local defaults
- Frontend component tests live beside the components they test and are matched by vitest's src/**/*.{test,spec}.{ts,tsx} pattern; Playwright specs live in e2e/ to avoid collection by Vitest
- Backend container runs as an unprivileged user (uid 10001) and defines a HEALTHCHECK against /health
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Frontend requests to the backend fail with a CORS error in development | Ensure the backend is running and, if accessed from a non-default origin, set ALLOWED_ORIGINS on the backend to include that origin (defaults allow http://localhost:5173 and http://127.0.0.1:5173) |
| `npm run build` succeeds but the app has type errors | Run `npm run typecheck` (tsc --noEmit) separately, since build does not typecheck |
| `pytest` fails with `ModuleNotFoundError: No module named 'app'` when run from elsewhere | Run pytest from the backend/ directory so pytest.ini's pythonpath = . setting resolves correctly |
| Playwright e2e tests fail to start the backend | The webServer config expects a backend/.venv with packages installed; create and populate that virtualenv (pip install -r backend/requirements.txt into backend/.venv) before running npm run test:e2e without E2E_BASE_URL |
| Port 5432 or 6379 already in use when running docker compose up | Stop any local Postgres/Redis instances or adjust the port mappings in docker-compose.yml |
